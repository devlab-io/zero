# Zero Devlab « extraordinaire » — recherche de cadrage

*Rapport de recherche — 2026-07-06. Orchestration : Jarvis (Claude) ; chercheurs : Codex gpt-5.5, 2 vagues (scout + 5 fronts + experts/sécurité), ~100 recherches web. Sources primaires vérifiées ; affirmations porteuses recoupées ≥2 sources indépendantes ou vérifiées localement dans le repo.*

## Réponse d'abord (BLUF)

1. **L'upstream Mail-0/Zero est effectivement mort ; notre fork est la branche vivante.** Branche par défaut `staging` figée au 2025-08-31 ; `main` : 5 commits depuis avril 2026, le dernier intitulé « ugh » (2026-05-26) ; issues fermées à la création ; ROADMAP datée fév. 2025 [vérifié localement + S5-05, primaire]. Conséquence : **divergence assumée** — pas de cadence de rebase, cherry-pick opportuniste seulement. On construit pour nous.
2. **Contrainte licence réelle mais bornée** : MIT au top-level, mais **7 fichiers / 403** portent un en-tête « reuse or distribution requires a license from Zero Email Inc. » — concentrés dans `workflows/` (sync), `routes/agent/` (MCP) et `lib/analyze` [vérifié localement, exhaustif]. Usage interne : sans risque. **Redistribution du fork : à proscrire** tant que ces fichiers n'ont pas été réécrits.
3. **Architecture agent : draft-only, MCP-first.** Le MCP de Zero expose aujourd'hui `sendEmail` et **pas** de `createDraft` [vérifié dans notre code, ligne 238] — c'est exactement l'inverse du consensus sécurité (Nylas : « un agent qui ne doit que labelliser et rédiger ne doit jamais détenir l'outil send » ; Willison : la « lethal trifecta » = données privées + contenu non fiable + canal sortant). Chantier n°1 de l'agent : **ajouter createDraft, retirer sendEmail du MCP**, et brancher Codex CLI (0.142.x, client MCP Streamable HTTP + OAuth natif — confirmé docs OpenAI).
4. **Performance : le levier est local-first, pas serveur.** Gmail plafonne à 6 000 unités/min/utilisateur et `messages.get` coûte 20 unités — le corps des mails est l'étape chère ; push = 1 evt/s/utilisateur, droppable, `historyId` périssable (parfois quelques heures) → architecture obligatoire : watch+Pub/Sub **plus** fallback `history.list`. La sensation Superhuman vient d'une DB locale navigateur + préchargement (<100 ms perçu). Notre stack a déjà les briques (DO cache, Hyperdrive ~320 ms en cache) ; le manque est **côté client** : cache IndexedDB persistant + optimistic UI systématique. Au passage : remplacer virtua 0.41 (0,7 M dl/sem) par tanstack-virtual (16,2 M dl/sem) lors du chantier liste.
5. **File de brouillons : outbox Postgres + idempotence, pas de nouvelle infra.** `drafts.create` est officiellement **non idempotent** et un 200 Gmail **ne garantit pas l'envoi** [docs Google, primaires] → table outbox transactionnelle dans notre Postgres (pg-boss v12, SKIP LOCKED, actif — ou alarms DO si l'on reste CF-natif), clés d'idempotence applicatives, undo-send par délai artificiel 10-30 s avant `drafts.send` (pattern Apple/Outlook). Analogue produit validé : Shortwave+Tasklet (brouillons déposés en revue dans l'inbox) et Inbox Zero (#276 : webhook → règles → draft ; #1164 : follow-ups annulés si réponse).
6. **UX : le pattern roi est discoverability → muscle memory.** Cmd-K qui *enseigne* la touche (Superhuman), splits = vues requêtées actionnables (≤7), triage « get to zero » une-décision-une-touche avec avance auto (déjà posé chez nous : d/r/a/f/h), IA exposée en primitives clavier (ghost-text Tab, Y=ask) — jamais en chatbot séparé. Contre-signal à respecter : Notion Mail ferme le 2026-09-22 ; les vues IA « magiques » séduisent puis déçoivent (labels erratiques, fiabilité) — l'IA doit rester **prévisible et annulable**.

## Le brief, restaté

Fork devlab-io/zero (self-host, 5 boîtes Gmail Workspace devlab.io) → niveau extraordinaire : (1) performance, (2) UX clavier, (3) agent local Codex CLI préparant des brouillons sous garde-fous, (4) mini-feature file de brouillons. Décision informée : roadmap du fork + architecture agent. « Répondu » = plan d'exécution priorisé, risques nommés, chiffres sourcés.

Constats croisés GitHub (chercheur 5) + git local (`git log upstream/staging -1` → 2025-08-31 ; 5 commits sur main depuis 2026-04). Zero Email Inc. : YC-backed, présence légale active, aucun signe public de pivot/faillite — mais aucun signe de vie produit non plus [UNVERIFIED sur les causes]. Assurance : Inbox Zero (11,5k★, commits < 7 j, 84 issues ouvertes actives) est le comparateur vivant le plus proche.

### B. Performance — VERIFIED (chiffres) / baseline locale à produire
Quotas [Google, 2026-06] : 1,2 M u/min/projet, 6 000 u/min/user ; `watch`=100u, `history.list`=2u, `messages.list`=5u, `messages.get`=20u ; batch ≤100 (>50 déconseillé), le batch ne réduit PAS le quota. Push : renouveler watch ≤7 j (recommandé quotidien), 1 evt/s/user, excès droppés. Hyperdrive [CF, 2025-04] : 1200→500→320 ms (direct/HD/HD+cache). DO : placés au premier get, ne migrent plus. R2 : bench CF 2023 favorable, bench concurrent Tigris 2026 défavorable — **DISPUTED**, workloads non comparables ; à mesurer sur notre cas. Superhuman [primaire, 2022] : DB locale, préchargement/prérendu, cibles <100 ms/<50 ms/<32 ms. Virtualisation : tanstack-virtual v3.14 domine l'écosystème ; react-window v2 documente que les hauteurs dynamiques restent moins efficaces. **Ce qui changerait la conclusion** : une baseline de notre instance en build prod (pas dev) montrant que le goulot est ailleurs (ex. Hyperdrive froid, DO mal placé vs nous en Pacifique — point non couvert par les benchs publics, tous US/EU).

### C. UX — VERIFIED
Superhuman [docs primaires] : Cmd-K affiche le raccourci à droite (« watch the letter that appears on the right ») ; splits ≤7 recommandés, compteurs masqués à zéro ; get-to-zero = J/H/E avec avance immédiate ; snippets avec variables + alerte pré-envoi si placeholder non remplacé ; « Get Me To Zero » bulk avec 7 j d'undo. Shortwave : Y=ask AI, Ctrl-J assistant, ghost-text Tab (2024-01), filtres IA en langage naturel. Missive : à retenir pour plus tard (commentaires d'équipe dans le mail — pertinent si Shane/Omar rejoignent l'outil). NN/g : <0,1 s instantané, indicateur de progression >1 s, skeletons pour pages entières. React 19 `useOptimistic` natif.

### D. Agent local — VERIFIED / mitigations = décision d'architecture
Codex CLI [docs OpenAI, accédées 2026-07-06] : `[mcp_servers.X]` avec `url`, OAuth (`codex mcp login`), `tool_timeout_sec` 60 par défaut, politique d'approbation par outil (`approval_mode`) ; `exec --json` (JSONL : thread.started/turn.completed/item.*) pour l'orchestration ; `codex mcp-server` pour l'inverse. Better-auth MCP plugin : OIDC, **bientôt déprécié** pour l'OAuth Provider Plugin — prévoir la migration. Surface MCP Zero réelle (notre code) : 15 outils dont `sendEmail`, sans `createDraft` ; `bulkDelete`/`bulkArchive` commentés. **Menace n°1 documentée** : injection de prompt via mail entrant (CVE-2026-26133 Copilot ; Gmail/Gemini texte caché blanc-sur-blanc 2025-07 ; arXiv 2026-05 : la séparation data/instruction ne détecte pas la manipulation contextuelle). Mitigations, par ordre de praticabilité pour nous : (1) **tool-gating strict** — l'agent ne détient QUE list/get/label/createDraft, jamais send [OWASP + Nylas, consensus] ; (2) **sanitization HTML** des corps avant contexte agent (texte caché, markup exfiltrant) — nécessaire mais pas suffisante ; (3) **spotlighting/datamarking** du contenu non fiable [Microsoft 2025-07] — probabiliste ; (4) CaMeL [DeepMind 2025] — le plus fort sur le papier (67 % AgentDojo avec sécurité prouvable) mais artefact de recherche, **aucune adoption produit trouvée** — pas pour nous à court terme.

### E. File de brouillons — VERIFIED
CF Queues : 5 000 msg/s, batch 100, `delaySeconds` ≤24 h, backlog 25 GB, 1 M ops/mois inclus puis 0,40 $/M — mais dev local sans concurrence consumer. DO alarms : 1 alarme/DO, at-least-once, backoff dès 2 s, ~6 retries, pas de SLA de précision publié. pg-boss v12 (publiée il y a quelques heures au moment de la recherche, MIT, SKIP LOCKED) ; graphile-worker 0.17.2 (259k dl/sem). Gmail : `drafts.send` supprime le draft et crée un message neuf (ID nouveau) ; création de draft non idempotente [métadonnées MCP Google officielles] ; « You can't assume that a 200 response means the email was successfully sent » [doc Google]. Pas de scheduled-send dans l'API (le produit Gmail l'a, pas l'API).

## Carte des positions d'experts

**Vohra** (Superhuman/Grammarly, 2025-07) : l'email comme socle d'une « suite de productivité AI-native » — COI fort, vend cette vision. **Lee** (Shortwave, 2025-10) : autonomie assumée, Tasklet « works 24/7 without your input » — COI fort. **Steinbock** (Inbox Zero, 2025-2026) : philosophie draft-first, « triages, labels, and drafts replies in your voice » — COI (produit concurrent) mais aligné open-source. **Willison** (indépendant, 2025-06) : lethal trifecta ; le pattern dual-LLM qu'il a lui-même proposé est « flawed », CaMeL le corrige. **Google** (2026) : defense-in-depth + Model Armor — COI vendeur. **Le désaccord structurant** : Shortwave pousse l'autonomie totale exactement là où Willison place la zone rouge. **Notre arbitrage** (aligné Steinbock/Willison) : autonomie sur la *préparation*, humain sur l'*émission*. C'est aussi ce que nos gardes-fous Devlab imposaient déjà.

## Roadmap qui en découle (proposition, par ordre)

1. **W1 — Sécuriser le socle agent** : fork du MCP (createDraft in, sendEmail out, scoping par connexion), pipeline de sanitization HTML, config Codex `~/.codex/config.toml` vers `/mcp` + OAuth better-auth. Petit, débloque tout.
2. **W1-W2 — File de brouillons** : table outbox Postgres + pg-boss, statuts (queued→generating→draft_ready→approved→sent|cancelled), vue de revue dans Zero (approve = one-key, réutilise d/r/a/f/h), undo-send 15 s.
3. **W2-W3 — Perf** : baseline build prod (Lighthouse + traces), cache tanstack-query→IndexedDB, optimistic UI partout, préchargement du fil suivant (pattern Superhuman), migration virtua→tanstack-virtual, tuning sync (batch bodies ≤50, backoff canonique).
4. **W3+ — UX signature** : Cmd-K enseignant (hints de touches), splits Devlab (Relances, Factures/Kura, Clients, Interne), snippets FR/tahitien avec variables, ghost-text via IA locale.
5. **Continu** : divergence upstream documentée (`docs/FORK.md`), réécriture progressive des 7 fichiers restrictifs.
